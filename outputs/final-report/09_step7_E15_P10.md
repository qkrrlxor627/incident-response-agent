## ② 정의
### E15
- **기대**: async 서버에서 세션 저장소가 이벤트 루프를 막지 않는다.
- **실제**: 동기 `sqlite3`를 이벤트 루프에서 직접 호출했다. 연결 하나를 모든 요청이 공유했고, 인덱스가 없었다.
- **증거**: `outputs/before/captures/code/C13_E15_sync_sqlite_session.png`

### P10
- **기대**: `SUPERVISOR_VERSION=v1`로 롤백해도 장애 질문에는 모니터링을 조회한다.
- **실제**: v1은 LLM 응답에 "도와드릴까요"가 있을 때만 조회했다. 이 문구는 fake LLM 전용이다. 대상도 auth-service로 고정이었다.
- **증거**: `outputs/before/captures/S9_v1_no_monitoring.png`, `code/C11_P10_v1_rollback_condition.png`

## 트레이드오프
- 호출마다 연결을 여는 비용이 있다(로컬 파일이라 ms 미만). 대신 스레드 간 공유 연결의 경합 위험이 사라진다.
- `to_thread`는 기본 스레드 풀을 쓴다. 동시 요청이 아주 많으면 풀 크기가 한계가 된다.
- v1의 장애 판단은 키워드 규칙이다. 키워드도 시스템 이름도 없는 장애 질문("결제가 안 돼요")은 일반 대화로 처리된다.
- LangGraph 공식 checkpointer(`AsyncSqliteSaver`)로 바꾸는 것은 하지 않았다 → 한계에 기록한다.
